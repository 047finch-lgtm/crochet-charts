# 数据模型以网格为基础，不用 stitch graph

工程文件的核心结构是行优先的网格（`rows × cols` 个格子，每格 ≤ 一个符号），不采用 CMU knitdb / fossasia 主张的线圈拓扑 stitch graph。钩针往返图解的阅读和绘制本身就是逐格心智模型，网格模型对目标用户（业余爱好者）更直觉、实现更小；文件格式带 `formatVersion`，为将来演进留门。

## Considered Options

- **stitch graph（线圈拓扑）**：表达力更强（不规则结构、机器编织），但对往返图解是过度设计，且无成熟的编辑交互先例。
- **网格模型（选定）**：Stitch Fiddle 等主流编辑器的实际做法；代价是环形/不规则图解表达不了——已明确排除出一期（SRS §1）。

## Consequences

- 二期环形圈钩需要辐射坐标系，届时是扩展 `Chart` 还是引入第二种图谱类型，需要新 ADR。
- 4 万格上限（200×200）写入模型约束，渲染与存储都按此预算设计。
