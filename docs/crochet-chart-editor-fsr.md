# 毛线图谱编辑器可行性分析报告（FSR）

**结论：可行（GO）。** 技术路线每个选型都有同构先例，无未知技术；竞品格局存在真实空档（纯 Web + 本地存储 + 中文符号 + 无水印免费）；估算总量 450–650 小时，单人业余可完成。主要风险不在"能不能做出来"，而在编辑器交互细节的工时超预期与单人开发的连续性。

事实依据：[竞品格局与领域事实](research/crochet-chart-editor-landscape.md)、[竞品技术栈](research/crochet-chart-editor-tech-stacks.md)。本文只承载决策、结论与估算；事实细节一律查调研文档，不在此复述。

## 1. 产品共识（已锁定）

| 决策         | 结论                                                               |
| ------------ | ------------------------------------------------------------------ |
| 目标用户     | 业余钩针爱好者（易用、好上手、方便分享优先于出版级排版）           |
| 针法范围     | 只做钩针；图解形态只做往返矩形网格                                 |
| 形态         | Web 应用（PWA 兼顾离线），纯本地存储（IndexedDB），无账号无后端    |
| 技术栈       | TypeScript + React + SVG，单人业余时间开发，零预算                 |
| 符号         | 日式 JIS 画法 + 中文缩写惯例（X/T/F/V/A）为默认，标注美式/英式术语 |
| 差异化优先级 | ①免费无账号无水印 > ②中文优先 > ③极致易用                          |

**排除项**（及去向）：环形圈钩图解（二期第一批）、棒针（二期）、图片识别导入（技术不成熟，长期搁置）、多人协作与云同步（验证需求后再议）、社区（产品化阶段）。

## 2. 技术可行性

| 关注点    | 选型                                                                                               | 同构先例（详见技术栈调研）                                                                                                      |
| --------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 渲染      | SVG DOM（符号即 SVG 元素）                                                                         | Stitch Fiddle、Stitchmastery、Stitch Works、sconcho、knitscape 全部收敛于 SVG 输出；HookChart 走 Canvas 自认高清导出未成        |
| 数据模型  | JSON 网格模型：`rows × cells → {symbolId, color}`，行列元数据（编号/重复标记）单独存               | knitscape 的 JSON workspace（符号与颜色分离）；stitch graph（knitdb）作为格式演进方向，MVP 不需要                               |
| 工程文件  | 单 JSON 文件，可导入导出                                                                           | 业界工程格式互不通用（.knt2/.pattern/.spf），自定 JSON 即可，版本号字段留迁移余地                                               |
| 符号库    | 30 个常用符号，SVG 图形自绘 + 元数据（名称、中英术语、行高）；预留自定义符号接口                   | 符号即 SVG + 元数据 = sconcho / Stitch Works 的成熟做法；JIS/CYC 均约 20–31 个即覆盖主流                                        |
| 撤销/重做 | 命令模式                                                                                           | Stitch Works（QUndoStack）、sconcho 同款架构                                                                                    |
| 存储      | IndexedDB 多文件管理 + JSON 导出备份                                                               | 零后端约束下唯一合理解                                                                                                          |
| 导出      | PNG（SVG 光栅化）、SVG 原生序列化、PDF（打印管线：print CSS + `beforeprint`；svg2pdf.js 作进阶项） | Stitch Fiddle 的 `/print` 路由即打印管线；Chart Minder 同样 "print it"；PDF 随导出附带图例（key），行业规范要求图解必须自带 key |

**结论**：无技术不确定项。所有风险集中在编辑器交互语义（行列插入删除时网格如何变形、重复区标记怎么交互）——这正是 Stitch Works 网格吸附/镜像 bug 的产地，属于工时风险而非可行性风险，用 M1 的出口标准兜住。

## 3. 竞品格局（摘要）

完整对比见[竞品格局调研](research/crochet-chart-editor-landscape.md)。要点：

- **Stitch Fiddle**（Web SaaS）功能最全，但英文、云端+账号、免费版有水印与额度限制——被 ①② 直接击中。
- **桌面老牌**（Stitchmastery £70 买断、Stitch Works 停更开源、KnitBird 停维护）技术栈老化、上手门槛高——被 ③ 击中。
- **国内新工具**（编织助手/团团织/Yarnbie）集中在 iOS/小程序，**纯 Web 本地优先是空档**；HookChart（Web beta）要求登录且高清导出未完成。
- 市场热度佐证：小红书 #钩针编织 32.4 亿浏览、编织人生会员 253 万、美国 CYC 调研 48% 以钩针为主——业余爱好者盘子足够大，且本项目零成本运营，无盈亏平衡压力。

## 4. 工作量估算与里程碑

估算口径：理想全职人时（含设计、测试、打磨）。每周 10 小时换算按每月 ≈ 43 小时计。

| 里程碑            | 内容                                                                        | 估算      | 出口标准（全部满足才算完成）                                            |
| ----------------- | --------------------------------------------------------------------------- | --------- | ----------------------------------------------------------------------- |
| M0 骨架           | 工程搭建、JSON 数据模型、SVG 静态渲染一张图谱                               | 40–60 h   | 给定 JSON 能渲染出含 ≥5 种符号、行号、图例的图谱，浏览器缩放无损        |
| M1 编辑核心       | 逐格绘制/擦除、符号切换、颜色、撤销/重做                                    | 120–180 h | 可徒手画出一张 30×30 图解；任意操作序列后撤销栈 100% 可回退，无历史错乱 |
| M2 符号与结构编辑 | 30 个符号库（JIS 画法+双语术语）、行列插入删除、重复区标记、行号自动重排    | 120–180 h | 30 符号全部可绘制且图例正确；任意行列增删后网格与行号保持一致，无错位   |
| M3 文件与导出     | IndexedDB 多文件管理、JSON 导入导出、PNG/SVG/PDF（含图例排版）              | 90–130 h  | 三种格式导出均可打印级清晰；导出含完整 key；刷新/关浏览器后数据不丢     |
| M4 打磨上手       | 2 个示例图谱、三步引导、性能（100×100 网格流畅）、跨浏览器（Chrome/Safari） | 60–100 h  | 新用户 10 分钟内画出第一张图（真人验证）；100×100 绘制无感知延迟        |

**总量 430–650 h**：每周 10 h → 约 10–15 个月；每周 20 h → 约 5–8 个月。AI 辅助开发可压低实现工时，但 M4 的真人验证不可压缩。

## 5. 风险与缓解

| 风险                                      | 等级 | 缓解                                                                             |
| ----------------------------------------- | ---- | -------------------------------------------------------------------------------- |
| 交互细节超预期（行列编辑语义、镜像/复制） | 高   | M1 出口标准先行验证；功能砍到"逐格+行列增删"为止，更复杂编辑（区域变换）不进一期 |
| 单人业余开发断档                          | 高   | 里程碑小步交付，每个 M 出口都是可用产品；断档损失 ≤ 一个里程碑                   |
| PDF 排版在不同浏览器不一致                | 中   | 打印管线只承诺"可打印"，像素级一致不做承诺；svg2pdf.js 作兜底进阶项              |
| Safari 的 IndexedDB/打印差异              | 中   | 双浏览器列为 M4 出口标准                                                         |
| 符号画法版权                              | 低   | 符号图形全部自绘，只遵循事实标准画法（画法本身无版权，JIS 文本不引用）           |

## 6. Go / No-Go 条件

- **Go**：按上述共识开工，从 M0 起步。
- **转 No-Go 的信号**：M1 出口标准连续两次未通过（说明编辑器交互复杂度超出业余投入上限），或开发中断超过 3 个月（复盘后决定重启或归档）。
